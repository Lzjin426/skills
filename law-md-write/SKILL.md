# Law MD Write

Fullstop 本地 Markdown 笔记的写法规范。管三件事：**怎么写**（结构）、**怎么引**（链接与附件）、**怎么验**（可跑的扫描）。

**第一性目标：笔记要在四件事下都不坏——搬迁、合并、渲染、导出。** 下面每条规则都从这一条推出来，不是审美偏好。想往这份文档加规则，先问它服务于哪件事；答不上来就别加。

## 零、适用范围

- 管：本地 `.md` 文件。主库 `/Users/fullstop/Documents/知识库`，以及任何用 Obsidian 打开的库。
- 不管：飞书云文档排版（走 `lark-doc-tidy`）、知识内容与论证（走 `knowledge-doc-writer`）、图片 OCR 补录（走 `md-image-supplement`）、飞书转写（走 `lark-doc-in`）。
- **铁律：只改结构与写法，不改内容事实。** 发现内容问题（疑似缺段、编号跳号像漏了一节、前后矛盾）只在报告里单列，不擅自补写或删改。
- 参考材料原文与附件目录里的文件不适用本规范，扫描时跳过。

## 一、标题体系（硬约束）

正文第一个标题必须是 H1，逐级递进，且标题自带显式编号。

| 要求 | 说明 |
|---|---|
| H1 起头 | 有标题的笔记，第一个标题必须是 H1；不允许从 H2、H3 起头 |
| 逐级递进 | H1→H2→H3，不许跳级（H1 直接到 H3 是错的） |
| 显式编号 | 编号写进标题文本，不依赖插件渲染 |
| 编号与层级绑定 | H1 用 `1.` `2.`（带尾点）；H2 用 `1.1` `1.2`（不带尾点）；H3 用 `1.1.1`；H2 的编号跟着父级 H1 走 |
| 同级连续 | 不重号、不跳号、不用前导零（`01` 要写成 `1`） |
| 首标题不重复文件名 | 文件名就是笔记标题，正文第一个标题是第一节的名字，不要再抄一遍文件名 |
| 同深度不混用 | 同一层级要么都编号、要么都不编号，不许一半带号一半不带 |
| 允许前置引言 | H1 之前可以放一个引言块（`>` 引用或 `> [!note]` callout），写一句话结论 |
| 标题前后留白 | 标题独占一行，前后各留一个空行 |

对与错：

```markdown
✅ 宽径比.md
> 齿轮的齿宽与节圆直径之比。越大，齿轮越厚。

# 1. 基本定义

## 1.1 齿宽

# 2. 宽径比对性能的影响

## 2.1 承载能力

❌ 首标题是文件名 / 从 H2 起头 / 跳级 / 编号混用
# 宽径比            ← 和文件名重复
## 什么是宽径比      ← 从 H2 起头，且没编号
### 1.1 定义        ← 跳级
## 2. 承载           ← 尾点风格不统一
```

极短片段（一段引文、一条备忘）允许整篇没有标题，但**不允许以 H2/H3 开头**——那说明它本该有 H1 却被砍掉了。

## 二、引用与链接

1. **笔记互引一律用双链**：`[[笔记名]]`。目标只写文件名，不写相对路径、不写 `../`、不写绝对路径。搬迁和合并时靠文件名解析，路径一写就断链。
2. **禁止裸引用**。以下写法一律改掉：
   - `见 1.1 节` → 改成 `[[目标笔记#1.1 名称]]`，或直接写成完整句子
   - `见表 3.1` → 说明这张表在哪篇笔记里，并给双链
   - `见 02-传动比分配.md` → `[[02-传动比分配]]`
3. 需要显示别名用 `[[文件名|显示文字]]`，目标部分仍然只写文件名。
4. 引用外部文献（原书章节、标准、论文）时，指向本地对应笔记或原文文件，不写“同书”“见前文”这类依赖上下文的说法。

## 三、附件与图片

1. **附件统一放在库根的 `附件/` 目录**（Obsidian 已配置 `attachmentFolderPath: 附件`，粘贴自动落位）。
2. **引用只写文件名**：`![[图片名.png]]`。不写路径，不用 `![](../附件/x.png)` 这种形式。
3. 从外部迁移（飞书等）下来的图片，**沿用来源的 token 名**（如 `B43mbcBTgoHKloxXmdVcFGlnnfc.png`）。这类名字稳定、不重名，跨库合并时不会撞车；不要为了让名字好看而重命名，也不要塞进 AI 生成的图片描述。
4. 正文配图不要用远程外链（`![](https://...)`）。先下载到 `附件/` 再引——外链会失效，也带不进导出件。
5. Excalidraw 嵌入用 `![[文件名.excalidraw.md|800|center]]`，宽度按需改，`center` 控制居中。
6. 同一个附件只存一份。发现重名不同内容时先比对再决定保留哪个，不要直接覆盖。

## 四、公式

1. **行间公式必须独立成段**：`$$` 单独一行，公式内容单独一行，`$$` 再单独一行，前后各留一个空行。这样渲染才会居中，也是“排版看着乱”最常见的根因。
2. **不要在行内使用 `$$`**。行内公式用单 `$...$`。
3. 公式里的符号要与正文用法一致（同一个量不要一处写 `H_sp`、一处写 `H_{sp}`）。
4. 公式编号写在公式行内（`\tag{2-1}`），编号连续，引用时指向编号并说明出处。

```markdown
✅ 行间公式独立成段                ❌ 行内 $$ 挤在段落里
$$d_b = d \cdot \cos\alpha$$      由此得 $$d_b$$ 为基圆直径，其中 $$d$$ 是分度圆。
```

## 五、空白与分隔

1. 连续空行最多留一个。多余空行是“特别大的空白”的直接来源。
2. 文末保留一个换行，不要留一串空行。
3. `---` 只用来分隔顶层 H1 之间的大段落（长笔记里有用），不当装饰线、不连着写两条。
4. 列表项前后不额外加空行；嵌套列表靠缩进，不靠空行。

## 六、frontmatter

1. 只在真需要时才加，只放**结构元数据**：`note_type`、`layer`、`prerequisites`、`next`、`skip`（跳过自动编号）。
2. **不要在 frontmatter 里堆 wiki 链接**（`related: [[...]]`）来批量建图谱边——链接会脱离正文语境，搬迁时也不好维护。语义链接放正文。
3. frontmatter 与正文之间保留一个空行。

## 七、标点与中英混排

1. 中文内容用全角标点和中文引号（`“”`、`‘’`），不要用直引号包中文。
2. 中文与英文、数字之间加一个半角空格。
3. 但代码、公式、链接、版本号（`v1.2.3`）、百分比（`3.5%`）、文件名、`GB/T 3480.6` 这类标准号**不硬拆、不插空格**。
4. 已有空格不重复加；不确定时保持原样。

## 八、标准骨架

```markdown
> [!note] 一句话结论
> 这篇笔记回答什么问题。

# 1. 第一节

正文……

## 1.1 子节

正文……

---

# 2. 第二节

## 2.1 子节
```

顶层小节控制在 3–5 个。宁可少而深，不要把内容摊成一堆只有两三行的浅标题。

## 九、写与改的工作流

1. **先扫再改**：跑第十一节的扫描，拿到现状。
2. **只动结构**：标题层级、编号、引用形式、附件引用、空白、标点。内容一个字不改。
3. **小步替换**：用精准替换（`str_replace` / 块级替换）改具体位置，不要整篇 overwrite 重写——整篇重写会丢格式和链接。
4. **改完再扫**：同一批命令再跑一遍，确认违规清零且没引入新问题。
5. **回读**：抽查改动的文件，确认正文、图片引用、公式都还在。
6. **报告**：说清改了什么、还剩什么没改（含未处理的内容问题）。

大范围批量改动（整个库重排标题）动手前先给一份清单让用户过目，改完报告影响面。

## 十、外部来源迁移到本地库

从飞书等外部来源搬到本地笔记库时，按下表转换：

| 外部形态 | 本地笔记 |
|---|---|
| 文档标题 | 文件名；正文里重复标题的那一行删掉 |
| 正文标题层级 | 保留相对层级关系，从 H1 起头，重新编号 |
| 内嵌表格 / 电子表格 | Markdown 表格 |
| 文档引用、笔记互引 | 双链 `[[文件名]]` |
| 图片 | 下载到 `附件/`，保留来源 token 名 |
| 画板 | 单独高清导出为 PNG 再引，不要用预览缩略图 |
| Callout | Obsidian callout `> [!note]` |
| 网格布局 / 分栏 | 拍平为线性结构 |
| 附件（非图片） | 下载到 `附件/` |

**不要做层级降级。** 旧约定曾把正文 H1 降为 H2（“文件名即标题”那套），已废止——本地笔记从 H1 起头。迁移时若原文首标题就是文档标题，删掉它，其余标题保持原层级并从 H1 开始重排。

迁移完必须跑一遍扫描，重点看：首标题层级、编号连续性、图片引用是否带路径、有没有“见 xxx”漏网。

## 十一、校验

```bash
python3 ~/.skillsbase/skills/law-md-write/scripts/check_md_structure.py /Users/fullstop/Documents/知识库
```

只读，不改文件。检查项：首标题不是 H1、标题跳级、编号不连续、编号混用、首标题与文件名重复、行内 `$$`、连续空行、裸引用“见 xxx”、图片或双链带路径。传入其他库路径即可检查别的库。

## 十二、环境事实（2026-09-19 校准）

- 主库：`/Users/fullstop/Documents/知识库`，由“齿轮”“计算机基础”“工程基础”三个库合并而成。
- 目录：`00-inbox`（新笔记落这里）、`01-工程基础`、`02-齿轮箱`、`03-计算机`、`附件`。
- `.obsidian/app.json`：`attachmentFolderPath: 附件`、`newFileLocation: folder` → `00-inbox`。
- 自动编号插件 `auto-numbered-headings` v2.2.0：**只重排已经带编号的标题**，且要最浅层标题带尾点（`1.`）才会触发；它**不会**给没编号的标题补号。所以文本里必须自己写编号——这是“显式编号”规则的由来，不是可选项。
- 另一个插件 `number-headings-obsidian`（用户 fork 版，加了编号蓝色样式）也在启用列表里，两者职责重叠。改标题前先在 Obsidian 里确认渲染出的编号没有叠加。

## 十三、踩坑记录

- `顶层导航.md` 里写“附件统一落 04-附件”，实际目录名是 `附件/`，以 `.obsidian/app.json` 为准（文档会漂移，配置不会）。
- 库内目录名会变（`01-参考材料` → `01-材料`、`03-基础知识` → `02-基本知识`）。脚本里跳过参考材料的规则要跟着调，否则会把原文当笔记报错。
- 年份会被误判成标题编号（`## 2020 年代的复兴`）。脚本已排除 4 位以上数字段，手写脚本时记得同样处理。
- 起头层级不对的文件再报编号错没有意义。扫描时先判层级、跳过编号核对，否则一次刷出几十条噪音，真问题会被埋掉。
- 同一天里，同一个迁移任务如果由不同工具（Antigravity / Qoder）分别执行，会产出两套风格。规范要写在一处、能被所有 agent 读到，否则每次迁移都重来一遍。
