# Lark Wiki Tidy

Fullstop 的飞书知识库治理规范。管两件事：**体系**（库怎么分类、什么颜色、什么结构）和**流程**（怎么盘点、怎么改、什么时候能动手）。

**REQUIRED SUB-SKILL:** 所有飞书读写先调用 `lark-wiki`（认证、node、space 命令约定）。本文只讲治理规则与本库特有的操作要点。

## 一、知识库分类体系（两色规范）

知识库只分两类，封面颜色就是分类标签：

| 类别 | 封面色 | 包含 |
|---|---|---|
| 理论学习（长期参考） | 蓝 #245bdb | 疲劳理论、风电齿轮箱设计、工程基础、计算机基础、齿轮箱资料、文献 |
| 其他一切 | 绿 #62d256 | 工程项目（恒润/实验台/CRRC/10MW/300KW/金风/传动实验台）、学术成果（学位论文/小论文）、长期课题、日常记录（note2025）、规范与公开库（代码规范/其他/匈牙利） |

封面规则：

- 一律用纯色封面，从设置页"色彩"分类里选固定色块，不用图片封面、不随机。色块源图 token：蓝 `fc97b052`、绿 `55bacacd`（保存后服务端会生成处理副本，蓝色副本 `667f2aeb`、绿色副本 `16aaacff`，验证时认副本即可）。
- 图标是系统按名称首字自动生成的方块，**不可自定义颜色和文字**，不要在这一步浪费时间。
- 新库创建后第一件事：按类别设置封面色。

## 二、库结构治理原则

1. **一个库一个主题。** 库要有明确主题；过散、变成收容所的库要拆掉，文档按主题归到其他库或新建主题库（"BASE"库因此解散）。判断标准：向陌生人解释这个库装什么时，一句话说不清 → 该拆。
2. **单篇库不保留。** 只剩一两篇文档且与其他库主题重合的库，把独有内容并入目标库后删除整个库（如"上海电气 6.25MW"参数并入齿轮箱资料后删库）。
3. **合并优先于共存。** 同主题短文档并入该主题的主文档（如"阻尼与摩擦"并入"NVH"、"预紧力"并入"紧固件"、"什么是载荷谱"并入"载荷谱体系概述"），用 `docs +update --command append --doc-format markdown` 追加，加一级标题分节，然后删除原节点。
4. **移位优先于复制。** 文档放错库/错分组时用 `wiki +move`（可跨 space，`--target-space-id` + `--target-parent-token`），不要复制粘贴造副本。
5. **库内用分组组织。** 文档超过 ~5 篇就按子主题建父节点分组；分组名用主题词，不用"新建分组"这类默认名。
6. **命名纪律。** 库名/文档名不带"副本""（废除）"等字样；发现带"副本"的确认内容重复后删一份；"（废除）"标注的旧方案不擅自处理，问用户。
7. **归档库到期处理。** 按年份的 note 库（note2025）在新一年出现后只读化：改名加"归档-"前缀或整体说明后保留，不再往里放新内容（具体方式问用户，没有自动归档机制）。

## 三、工作流纪律（用户规矩，硬约束）

1. **讨论只动嘴，动手等批准。** 盘点、给建议、列方案阶段一律只读；迁移、合并、删除、改名必须等用户明确说"做/可以/执行"才动手。用户已批准的批注或指令视为许可，不重复确认。
2. **整理节奏：** 先全量盘点（`wiki +space-list` + 每个 space `+node-list`，含分组子节点）→ 输出结构化盘点（每库：文档数、主题、问题）→ 给"删除/合并/移位/保留"四类建议 → 用户批准 → 批量执行 → **逐条回读验证**（node-list 复查 + 封面取色验证），最后汇报每库最终结构。
3. **删除是高风险操作。** 删节点/删空间前确认独有内容已转移——**删空间会连带删掉里面的所有文档**（曾有把空间当容器删、连带删掉两篇论文的教训）。删空间前必须先把要留的内容移出或确认无独有内容。
4. **新文档归位。** 需要用户自己消化的文档放云盘 Inbox 文件夹；日笔记/周笔记放云盘 note 年份文件夹（当前 note2026）；消化完的成体系知识归到对应知识库。

## 四、操作要点（踩坑记录）

### 盘点与批量操作（lark-cli）

```bash
lark-cli wiki +space-list --as user                    # 全量空间清单（name/space_id/description）
lark-cli wiki +node-list --space-id <sid> --as user    # 根节点
lark-cli wiki +node-list --space-id <sid> --parent-node-token <pid> --as user   # 分组子节点
```

- node-list 的 JSON 大且字段顺序不定，**用正则提 token 不要 JSON.parse**：`/"node_token": "([^"]+)"[\s\S]{0,400}?"title": "([^"]*)"/g`
- 写操作间隔 400–800ms 防限流；删除带 `--yes`；`drive +move` 必须带 `--type docx`。
- docs 合并时注意：源文 `<title>` 行剔除；**画板 `<whiteboard>` 标签 append 会失败**——剔除标签、在合并稿里留一行文字说明和画板 token，并明确告知用户画板留在原文档（会随删除进回收站），需要手动搬。

### 改封面（最稳路径：Chrome 设置页 + Playwright）

空间设置页 URL 直达：`https://my.feishu.cn/wiki/settings/<space_id>`。用户的 Chrome 已登录飞书，在 Chrome 标签页里用 Playwright 操作比点客户端 GUI 稳定一个数量级：

1. `goto` 设置页 → 点"色彩"分类 → `locator('img[src*="<色块token>"]').first().click()` → 点"保存设置"（必须显式点保存，选了不自动存）。
2. **不要用 `evaluate` 读保存按钮 disabled 状态做判断**——点色块后按钮重渲染，旧句柄会读到假值。正确验证：保存后读 `naturalWidth === 432` 的预览图 src，比对处理副本 token，或下载取色（蓝副本 `667f2aeb`=#245bdb，绿副本 `16aaacff`=#62d256）。
3. 批量循环必须设足够长的执行超时（每个库约 8–10 秒），单次调用不要超过 4 个库。
4. Chrome 扩展未开"允许访问文件 URL"时 `filechooser.setFiles` 会报 Not allowed——所以用内置色块，不上传自定义图。

### 客户端 GUI（仅当 API/网页做不到时）

空间改名 API 不支持，只能客户端 GUI：知识库主页右键卡片 → 知识库设置。用 computer-use 操作。注意飞书自动更新后 AX 树会卡死，表现为只剩帮助菜单、截图不可用——重启飞书（进程名 `Feishu`，不是 `Lark`）后重绑即可。

### 已知的 API 假象

- docs_to_wiki 迁入后，Drive 文件夹 API 列表会有缓存残留；token 相同就是同一文档，**不要删残留**。
- 知识库图标、封面在开放 API 里均不可设置（`+space-create` 之后只能网页/客户端改）。
