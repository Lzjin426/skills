# lark-doc-tidy

**REQUIRED SUB-SKILL:** 任何飞书操作前，先调用 `lark-doc` 并遵循其认证、fetch、XML、update 必读引用。本 skill 只做格式规范化，不新增实质内容。

## 工作原则

1. **只改格式，不改内容。** 不增删论点、不改写句子。发现内容问题（编号跳号疑似缺段、句子截断）只在报告中提醒。
2. **默认全改，非必要不提问。** 用这个 skill 就是把文档格式整理到位：扫描后直接执行，改完输出变更报告；用户说"先看报告再改"时才先报告等确认。只有缺文档链接/token、或出现需要用户拍板的内容问题（如疑似缺段）时才开口问，其余一律先做后报。
3. **局部更新。** 用 `docs +update` 精准编辑（`block_replace` / `str_replace` / `block_delete`），不 overwrite 全文。
4. **改完回读验证。** 格式生效、内容没丢、无关块没动、结构没退化（标题还是标题、列表还是列表）。
5. **清单是引导，不是教条。** 每条只给"看什么、往哪个方向调、哪些地方要小心"；拿不准的宁可在报告里提醒用户，也别硬套。

## 排版检查清单

| 项 | 看什么 | 处理方向 |
|---|---|---|
| 总标题 | 正文第一个 h1 是不是在充当文档总标题（与标题栏重复，或全文唯一 h1） | 总标题归飞书标题栏，正文从 h1 开始；见「总标题」 |
| 标题层级 | 层级跳级（h1 直接接 h3/h4）；正文顶层不是 h1；全篇顶层级别不一致（如正文从 h2 开始、尾部却冒出 h1） | 逐级递进 h1→h2→h3；**正文顶层必须是 h1 且全篇顶层统一**：总标题处理后正文整体低一级（h2 起）就整体提升一级，尾部混入更高层标题就降为与正文顶层一致；改后检查正文里"见 1.1 节"这类引用是否失效 |
| 标题编号 | 手打编号、同级编号体系混用 | **要不要编号由模型按文档性质判断**：长文档、章节型、正式报告、需要交叉引用 → 编号；短文档、对话式、随笔、导语型 → 可不编号。**一旦编号，必须用飞书原生自动编号（蓝色 seq）**：手打前缀（`1. `、`一、`）去掉、由 seq 承载，体系混用统一转原生。见「原生编号」 |
| 公式 | 行间公式是否独立成段、有无混在行内 | 独立成段的公式居中（`<p align="center">`）；改不了就报告说明；行内混排不动 |
| 列表 | 手打编号的段落、编号断裂 | 转真列表、修连续；转列表后不再首行缩进，报告中提一句 |
| 表头 | 表格首行样式不统一 | 全篇统一：按多数派决定是否加底色，首行加粗 |
| 代码 | 裸代码当普通段落 | 明显是代码的转代码块并标语言；拿不准只提醒 |
| 图片 | 图片位置/对齐 | 新图用 `docs +media-insert --align center --caption "说明"` 一步到位；已有图片块的对齐改不了，只提醒 |
| 标点引号空格 | 半角标点混中文、直引号包中文、中英文/数字挤在一起 | 全角化、换中文引号、补半角空格；先把代码/公式/链接圈出来不动；"3.5%""第3章""v1.2.3"这类连写不硬拆；已有空格不重复加 |
| 首行缩进 | 正文段落无缩进 | `text-indent="1"` 优先，不支持时用两个全角空格；全篇方式统一；标题/列表/引用/代码/表格/元信息行不缩进 |
| 空白 | 连续空行、多余分隔线、行尾空格 | 按「空行与分隔线」的节奏收敛：连续空行合并为 1、文末删空、`<hr>` 去重、行尾空格清理 |
| 写法统一 | 日期/时间/数字写法混用 | 只提醒，由用户决定 |

## 总标题（判断与处理）

有些 Markdown 编辑器把正文第一个 `#` 当作文档总标题，飞书不是：飞书标题栏（`<title>`）与正文 h1 是两回事。判定「总标题误用」：正文第一个 h1 与标题栏重复，或它像总标题且是全文唯一 h1。拿不准就只提醒。

处理：把文本写入标题栏（实测 2026-08-14：append 仅带 `<title>` 只改标题、正文不变），再删除正文里那个 h1：

```bash
lark-cli docs +update --doc "<doc_token>" --command append \
  --content '<title>总标题文本</title>'
```

删完检查正文顶层是否还是 h1：如果正文顶层变成了 h2，把全文标题整体提升一级（见检查清单「标题层级」）。

## 标题原生编号（要用编号时）

标题**要不要编号由模型判断**（长文档/章节型/正式报告通常要，短文档/对话式/随笔可不编）；**一旦编号，就用飞书原生自动编号（蓝色、自动递增），不手打。** 蓝色自动编号可以写入，走 docs_ai 通道的 XML 属性，不是 docx v1 块模型：

```xml
<h1 seq="auto" seq-level="auto">第一章 概述</h1>
<h2 seq="auto" seq-level="auto">背景</h2>
```

- `seq="auto"` 自动连续，具体数字则从该数字重排；`seq-level="auto"` 层级随标题级别自动计算（h1→1、h2→1.1）。
- 手打编号前缀（`1. `、`一、`）从文字移除、由 seq 承载。**注意**：中文数字标题（`第一章`）会变成阿拉伯数字显示，属预期变化，在变更报告中注明即可。
- 验证必须用 `docs +fetch` 的 **XML** 格式（markdown 导出和 docx v1 都看不到 seq，会误判"编号被删"）。
- 该能力未写入官方公开文档，属隐藏通道，未来可能变动。只对决定要编号的标题执行；不编号的标题（如附录类：相关文档、附录、致谢、参考文献）不加 seq。

## 空行与分隔线

**空行（回车/空段落）的节奏：**

- 连续正文段落之间**不垫空行**（飞书段落自带间距）；空行是"换气"，只在主题切换、大章节之间（标题前）用，最多 1 个；
- 标题与它下面的正文之间**不垫空行**（标题样式自带段距）；
- 表格、图片、代码块与正文之间可留 1 个空行隔开；
- 文末不留多余空行。

**分隔线 `<hr>`：**

- 少用：只在**内容性质明显切换、且标题表达不了**的地方——如正文与附录（相关文档/参考）之间、长文总分界；
- 相邻正文章节之间用标题过渡即可，**不用分隔线**；
- 要用就单条；连续多条合并为一条。

Tidy 时按这个节奏收敛：连续空行合并为 1、文末删空、`<hr>` 去重、行尾空格清理；写作时直接按这个节奏落笔。

## 写作引导（新建文档时）

新建/生成文档时，把上面的检查清单当自查表逐项过一遍，一次写好；清单之外再注意：

- 标题要不要编号由模型判断（长文档/正式报告建议编号）；要编号就用原生自动编号 `seq="auto" seq-level="auto"`，附录类章节不编号；
- 流程/结构图用 Mermaid（自动转画板），保持简单，图表放在相关段落附近；
- 图片用 `docs +media-insert --align center --caption` 一步到位（居中 + 图注）；
- 关键结论加粗要克制，全篇加粗风格一致；
- 署名/元信息（作者、日期、来源）位置与格式全篇统一；
- 敏感信息（密钥、密码、未公开数据）写作前自查，不写进文档。

## 标准流程

1. **解析目标。** 用户必须给出文档 URL/token；没给才问一次。长文档用 `--scope` 分段 fetch（必读 `lark-doc/references/lark-doc-fetch.md`）。
2. **扫描并直接改。** fetch `with-ids` 拿 block ID，按清单逐项过、直接执行，不分批等确认。重点看标点/空格/空行/缩进/层级/编号/列表/表头；其余（公式、代码、图片、写法）扫到就报，不用深挖。拿不准的判定（代码块识别、总标题）不硬改，记进报告。执行顺序：先结构（列表 → 总标题 → 标题层级 → 标题编号 → 公式 → 代码块 → 首行缩进 → 表头），再字符（标点/引号/空格），最后空白（空行/分隔线/行尾空格）。分批局部更新，每批后按需重新 fetch 拿新 block ID；每批记录结果，失败重试一次，仍失败则跳过并记录。
3. **输出变更报告。** 改完汇报，格式：

   ```
   ## Tidy 变更报告
   - 文档：<标题>（URL/token）｜时间
   ### 已修改（N 处）
   | # | 类别 | 位置 | 修改前 → 修改后 |
   ### 未处理（M 处）
   | # | 类别 | 位置 | 原因 |
   ```

   字符级只贴差异片段；「未处理」含：⚠️ 失败（原因 + 位置，可重跑）、拿不准的判定、内容问题提醒、写法混用提醒。
4. **验证。** refetch 受影响区域：格式生效、内容没丢、无关块没动、结构没退化。原生编号用 XML 格式确认 seq 在位；总标题确认标题栏已更新、正文 h1 已删。最后幂等自检：全文再扫一遍应零改动（长文档可只重扫受影响块附近）；仍有改动说明实现有 bug（如空格重复加），修复后再报完成。

## 禁区（安全线）

- 不删除任何含实质内容的块；删除正文 h1 仅限总标题判定成立时（文本保留在标题栏，内容不丢），拿不准只提醒。
- 不改代码、公式、URL、引用原文、表格数据里的字符；做标点/引号/空格处理前，先把这些区域圈出来保护。
- 拿不准的判定只提醒不改。
- 不用 `overwrite` 重写全文——会丢划词评论、破坏画板引用、抹掉手动修改。
