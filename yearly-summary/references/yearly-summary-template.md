## 使用提醒

- 文件名使用 `YYYY年`（如 `2025年`），不带 `.md` 扩展名（飞书 docx 不需要）。年报直接写入飞书根目录（不是子文件夹）。
- **不写 frontmatter**（`---\ntags:\naliases:\n---`），飞书 docx 会忽略。正文从 `# 年度一句话` 开始。
- 每个 `#` 章节结束后插入 `---` 分隔线，最后一节不加。
- **图表章节正文留空**——`# 精力全景`、`# 里程碑时间线`、`# 年度心路` 三个章节的图表位置不写 mermaid 代码块。导入后通过 `lark-cli docs +update --mode insert_after` 在每个章节后插入空白画板，再用 `lark-cli whiteboard +update --input_format mermaid` 把估算后的图表内容写入。具体命令见 SKILL.md 步骤 6。
- 全年共 4 张图表，分别暂存为 `./pie.mmd`、`./gantt.mmd`、`./timeline.mmd`、`./xychart.mmd`，作为后处理步骤的输入：
  - `pie.mmd`：全年精力分布饼图，主题 3~6 个
  - `gantt.mmd`：全年项目时间线甘特图，按月分段
  - `timeline.mmd`：关键里程碑 timeline，按 Q1~Q4 分段
  - `xychart.mmd`：年度心路 xychart-beta 折线图，Q1~Q4 × 1~5 分（替代不被支持的 journey 图）
- 章节正文里的解读文字（如精力全景的 1~2 段趋势分析）写在 markdown 主体里，不进画板。
- **反公式化**：以上结构仅为骨架。章节可增删、合并、调序。图表在数据不足时可省略。每年的年总结应有不同气质。
- **文风**：允许第一人称，鼓励感性表达。像写给年末的自己，不像写给老板的汇报。
- **数据源**：主要从月报提炼，周报始终作为补充细节，日报仅在月报+周报均缺失时定向回退；不逐读 365 篇日报。
- `致自己` 章节没有格式限制，真诚即可。
- `新年展望` 不加 P1/P2 优先级标签，年度展望更适合用方向+期待的形式。
- 月报覆盖率低于 50% 时，应在年度数据章节后说明数据基础有限，结论仅供参考。
