# 飞书文档格式规范

本文件说明将翻译后的 Markdown 输出到飞书文档时应遵循的格式规则。

## 总体原则

当用户选择「生成飞书文档」时，最终产物必须**按飞书文档的原生渲染逻辑**组织，而不是简单地把本地 Markdown 塞进去。核心目标：列表、标题编号、图片、公式在飞书文档里看起来自然、规范、可直接阅读。

## 标题规范

### 文档标题

- 飞书文档有且只有一个文档标题。
- **Markdown 模式**：正文第一行必须是 `# 文档标题`。
- **XML 模式**：正文第一行必须是 `<title>文档标题</title>`。
- 文档标题下方不要再出现另一个 `#` 一级标题；正文章节从二级/三级开始。

### 章节编号

- 飞书文档自身有「自动编号」开关，但通过 API 创建时不能保证开启。
- 因此，**在生成飞书文档时，必须手动给标题加上显式编号**。
- 编号规则：
  - 一级章节：`## 1 引言`
  - 二级章节：`### 1.1 背景`
  - 三级章节：`#### 1.1.1 细节`
- 如果原文已有编号（如 "1 Introduction"），保留并统一成全角/半角一致；如果原文没有编号，按层级自动补上。
- 编号必须连续，不要跳号。

### 标题层级

- 不要跳级：## 之后接 ###，不要直接接 ####。
- 不要使用超过四级标题（####），需要更深层级时改用列表或加粗段落。

## 列表规范

### 无序列表

- 使用 `-` 作为列表标记，不要用 `*` 或 `+`。
- 示例：
  ```markdown
  - 第一项
  - 第二项
    - 子项 A
    - 子项 B
  ```

### 有序列表

- 使用 `1.`、`2.` 作为列表标记，不要用 `1)` 或 `(1)`。
- 如果需要自动编号，可以统一写 `1.` 让 Markdown 自动递增；但为了飞书渲染稳定，**建议显式写出序号** `1.`、`2.`、`3.`。
- 示例：
  ```markdown
  1. 第一步
  2. 第二步
  3. 第三步
  ```

### 列表嵌套

- 子列表缩进 2 个空格或 4 个空格均可，但同一文档内保持一致。
- 子列表标记与父列表不同（父用 `-`，子也用 `-` 即可；飞书会按缩进自动区分层级）。

## 公式规范

- 行内公式：`$...$`
- 块级公式：`$$...$$`
- 飞书对 LaTeX 支持较好，**不要**把公式转成图片。
- 带编号的公式在块级公式末尾写编号：
  ```markdown
  $$ y = f(x) $$ (1)
  ```

## 图片规范

- 图片必须居中、大小合适。
- **Markdown 模式**：图片默认左对齐。如需居中，可在飞书文档生成后用 XML 的 `align="center"`，或在 Markdown 中配合 `<center>` 标签（但飞书 Markdown 不一定识别）。
- **推荐做法**：生成飞书文档时使用 XML 格式，将图片包在 `<p align="center">` 中：
  ```xml
  <p align="center"><img src="图片URL或TOKEN" width="600" caption="图1 示例"/></p>
  ```
- 如果必须使用 Markdown，确保图片引用是相对路径且图片已上传到飞书可访问的位置。

## 表格规范

- 使用标准 GFM 表格：
  ```markdown
  | 列 A | 列 B |
  |------|------|
  | 1    | 2    |
  ```
- 复杂表格建议使用 XML：
  ```xml
  <table>
    <thead><tr><th>列 A</th><th>列 B</th></tr></thead>
    <tbody><tr><td>1</td><td>2</td></tr></tbody>
  </table>
  ```

## 特殊块

- **引用块**：使用 `>`。
- **代码块**：使用 ` ``` ` 并标注语言。
- **高亮框 / Callout**：Markdown 不支持，需用 XML `<callout>`。
- **待办事项**：Markdown 不支持，需用 XML `<checkbox>`。

## 输出方式选择

| 场景 | 推荐格式 | 说明 |
|------|---------|------|
| 简单文档，以文字和公式为主 | Markdown | 快速、易读 |
| 需要居中图片、复杂表格、Callout | XML | 控制力强，渲染稳定 |
| 用户要求「按飞书原生样式」 | XML | 最贴近飞书文档体验 |

## 与本地 output 的区别

- 本地 `output/<basename>_zh.md` 保持标准 Markdown，方便用户本地查看和二次编辑。
- 飞书输出可以是 Markdown 或 XML，取决于复杂度；必要时同时保留一份 `output/<basename>_zh_feishu.md` 或 `<basename>_zh_feishu.xml` 在 `script/` 中备查。

## 实用检查清单

生成飞书文档前确认：

- [ ] 文档标题唯一且位于最开头
- [ ] 章节标题已手动编号
- [ ] 标题层级没有跳级
- [ ] 列表使用 `-` 或 `1. 2. 3.`
- [ ] 公式使用 `$` / `$$`
- [ ] 图片已处理（路径正确、大小合适、尽量居中）
- [ ] 表格使用标准 GFM 或 XML
- [ ] 已运行 `review_md.py` 检查基础错误
