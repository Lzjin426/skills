# MonoCode 参考案例

依据：MonoCode 本地源码在 2026-09-25 的 `2bc69af` 检出，以及 `docs/screenshot.jpg`。以下是可迁移的设计观察；路径均相对于 MonoCode 仓库，仅供需要核对原实现时使用。目标项目不需要依赖这个仓库。

## 空间组织

- `src/App.tsx`：主结构是侧栏、顶部标签栏和主工作区；主区域可承载多个面板和终端停靠区。布局随当前任务变化，并非永远展示固定三栏。
- `src/chrome/Sidebar.tsx`：侧栏默认宽 260px，可拖动调整，并按窗口宽度限制上限。侧栏内用局部导航切换 Sessions、Inbox、Explorer、Changes 等内容。
- `src/chrome/TitleBar.tsx`：40px 顶部栏承载工作上下文标签；当前标签更突出，标题和元信息分级显示，长内容截断，标签可重排。
- `src/chrome/SurfaceTabs.tsx`：面板内部的次级标签高 36px，仅用于同一面板里的文件或视图切换，与顶部工作上下文标签分工。
- `src/surfaces/PaneTree.tsx`：主工作区支持分割、比例预览、拖动边界和放置提示；并排区域用于真实的内容比较或协作。

## 视觉规则

- `src/index.css`：用主题变量定义基础背景、内容色和强调色；浅色主题单独调整文字、链接与辅助色。`sidebar-glass` 与 `body-glass` 分层，避免整窗只有一块平面。
- 界面以低对比边线、轻微表面明度差和紧凑间距组织内容。选中标签、悬停、元数据和辅助操作各有不同强度；强调色使用克制。
- 具体强度可从 `src/chrome/TitleBar.tsx` 核对：分隔线约为内容色的 10%，未选中文字约 50%，悬停底色约 5%，选中底色约 10%。这展示的是相对层级，不是所有项目都应照搬的透明度。
- 标签同时展示主标题和条件性的次级信息；空间不足时隐藏次级信息，再截断主标题。MonoCode 使用约 10–13px 的紧凑文字，迁移到中文或不同屏幕密度时应重新验证可读性。
- `src/chrome/Composer.tsx`：输入区是工作流的一部分，包含上下文、工具、队列和发送状态，视觉上与对话内容相连，而不是孤立的表单。
- `src/chrome/Modal.tsx` 与 `src/chrome/Popover.tsx`：浮层有清楚的层级、边框和背景处理。弹层锚定触发点，并处理窗口边缘与遮挡。
- `package.json`：React 和 Tailwind 提供渲染与样式，HugeIcons 提供图标；这些工作区部件主要在项目内实现。迁移设计原则不要求移除目标项目已有的组件库。

## 平台边界

- `src-tauri/src/macos.rs`：macOS 侧栏模糊使用原生窗口处理；CSS 负责其上的着色。窗口按钮也与 40px HTML 标签栏对齐。这是平台实现细节，不应写成通用 CSS 配方。
- 截图中的精致感还依赖真实数据量、内容密度、状态反馈和窗口材质。只复制配色与圆角，无法复现完整效果。

## 迁移判断

优先迁移：区域职责、信息层级、紧凑密度、可调整布局、完整交互状态和真实渲染验收。

按需迁移：项目侧栏、顶部多任务标签、分屏、终端停靠区、macOS 玻璃材质。目标软件如果没有相应任务，应省去这些结构。
