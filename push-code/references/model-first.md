# 模型与不变量模板

用于 push-code 的完整门槛：新功能、跨模块、改标签/会话/存储/共享状态，或新增用户可感知规则。复制到任务记录或委派 prompt，填完并得到用户确认后再开工。轻量门槛只需入口与回归路径，不必整页。

## 1. 入口盘点

| 入口 | 触发 | 修饰键/按钮 | 当前处理位置 | 是否共用单一命令 |
|---|---|---|---|---|
| 侧栏文件行 | 左键 | 无 / Ctrl / 中键 / 右键 |  |  |
| 主页列表/卡片 | 左键 | 无 / Ctrl / 中键 |  |  |
| 搜索结果 | Enter / 点击 | 无 / Ctrl / 中键 |  |  |
| 文档内引用 | 点击 / 按钮 | 无 / Ctrl / 中键 |  |  |
| 快捷键 |  |  |  |  |
| 拖拽 / 外部打开 |  |  |  |  |
| 重启恢复 | 启动 |  |  |  |

没列全的入口就是未来的补丁。新增入口时先判定它属于哪个模式，不复制替换逻辑。

## 2. 状态矩阵

行 = 入口；列 = 当前状态 × 修饰键 × 持久化。每格写清楚：结果视图、活动标签、是否先保存、是否新标签。

| 入口 \ 当前状态 | 文档 | 画板 | 文件夹 | 草稿 | 功能页 | 锁定标签 |
|---|---|---|---|---|---|---|
| 普通打开 | 替换 | 替换 | 替换 | 追加 | 追加 | 右侧新开 |
| Ctrl/Cmd | 新标签 |  |  |  |  |  |
| 中键 | 新标签 |  |  |  |  |  |
| 右键菜单 |  |  |  |  |  |  |
| 重启恢复 |  |  |  | 不恢复 | 恢复视图 | 恢复锁定 |

建议把“修饰键”拆成独立列或独立表，避免大表失控。保存失败、外部修改、目标缺失这类异常单独加行。

## 3. 不变量

一句一条，能写成断言/类型就不只写注释。示例：

- `current` 有值 ⇒ tabs 中存在对应的 Doc 标签。
- 任何替换或关闭当前文档前先 `save_before`；保存失败不继续。
- 会话快照的顺序、锁定、活动项和视图来自同一个模型，不各自维护。
- 锁定标签不被普通打开替换、不被快捷键关闭，但可中键或菜单关闭。
- 视图决定活动标签：功能页没有活动文件标签。

## 4. 单一命令

- 打开/切换只有一个入口函数，用参数表达模式：`replace` / `new` / `beside`。
- UI 入口只收集参数，不复制替换、保存、回退逻辑。
- 目标已打开时统一“激活已有”，不新增重复标签。
- 新增状态型功能时，先问“它是否扩展同一个命令”；不要新写一套平行的打开路径。

## 5. 异常态

逐屏检查：空、加载、错误、保存失败、外部修改、权限/同步盘只读、缺失目标、离线。

## 6. 补丁分类

| 类型 | 判断 | 处理 |
|---|---|---|
| 规则变更 | 用户语义变了 | 更新决策记录和矩阵，再改代码；不要继续修旧规则 |
| 未枚举组合 | 某个入口 × 状态没写 | 补矩阵行/列和接线测试 |
| 隐式状态/架构耦合 | 多处字段不同步 | 收敛单一来源/单一命令，修一类而不是一处 |
| 验证缺口 | 单测过但真机错 | 补真机 E2E 或脚本场景 |

修复 commit 说明属于哪类、补了什么测试或文档；review 先看是否只修了表面。

## 7. E2E 场景模板

```text
黄金路径：<用户真实入口> → <预期视图/标签> → <保存/恢复结果>
原型对照：<位置/尺寸/出现时机/空态/错误态/减少动态>（有已通过原型时必填）
边界：锁定标签、功能页、草稿、缺失文件、保存冲突、重启恢复
长驻：<定时器/刷新/文件监视/同步盘> 连续 10–15 分钟 + 文件移走/只读/冲突副本
证据：真实窗口截图 PNG 绝对路径 + 操作步骤
未验证：明确列出没跑的组合
```

截图保存成文件并给绝对路径；编译和单测通过不能代替真实窗口结论。不能只用内部脚本命令（如直接调用 Workspace 方法）代替用户入口。用户报告的手感/布局问题按 P1 验收缺口处理，补矩阵和 E2E。测试库按仓库 AGENTS 的规则：自动化/脚本用隔离临时库，人工试用用指定试用库或其副本；不碰真实库，不强关用户窗口。

## 备注

探索型产品不可能零补丁；这套模板的目标是把“每功能 3～4 轮补丁”压到“一轮内收敛”，而不是承诺不再发现新问题。
