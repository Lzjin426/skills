# 任务范围与必要模型

只在重要产品语义、共享状态或存储风险需要澄清时读取。模型服务于本批实现，不追求覆盖整个产品。

## 一页任务契约

```text
本批用户结果：
明确不做：
真实基线与文件归属：
核心入口与预期结果：
必须保持的数据不变量：
主要失败场景：
必要检查与交付物：
起始时间、截止时间：
阻断与需要用户决定的问题：
```

范围已确认且没有新产品决策时，记录后直接开发，不为模板每一项重复询问用户。

## 什么时候补状态表

只有同一入口在不同状态下应有不同结果，且遗漏可能影响核心行为或数据时才补表。写清有差异的组合，不展开全部入口 × 状态 × 修饰键。

例如，替换正在编辑的文件只需明确干净、有未保存输入、保存失败三种结果；不自动把所有页面、所有快捷键、所有设备列进同一表。

共享状态说明唯一数据源与修改入口；能用类型、断言或现有命令保持不变量时复用，避免每个入口另写一套。

## 数据风险与验证

按本次变化挑必要场景：写入前基线检查、失败保留输入、并发修改、回滚或恢复、迁移旧版本。只对本批确实改变的风险做检查；不能以范围小为由跳过会丢数据的失败路径。

UI 检查写出真实入口、手势、可见结果和数据结果；同一份真实证据可供 review 复用。同步或后台任务的观察时间由风险与现象决定，计入批次预算，不为所有任务机械安排固定时长。

发现新问题先分级：核心需求或安全问题阻断；其他缺陷和增强进入后续项。需要更换架构时重新写本批契约，保存旧实现，不同时完成两套方案。

未覆盖项如实列出。用户中断验收、缺少真实服务或达到截止时间时，说明未验证边界，不冒充完成。
