# 有边界的技术调研

只在技术路线不确定、已有参考实现尚未核实，或新增依赖明显影响维护成本时读取。普通修复不强制调研。

## 调研要回答的决定

先写出一个待决定的问题，例如“复用已有文件传输层还是引入新依赖”。已有可靠答案就复用，先查本地源码和现有报告，再补官方资料或项目源码。

默认最多 20 分钟，计入本批预算。选最能回答问题的少量候选，不为凑数量扩展搜索。达到时限给出已有结论、不确定性及验证下一步；网络或账号缺失时明确边界。

## 输出

用短段落或小表说明：
- 推荐路线，以及它满足本批范围的理由。
- 重要替代方案与实际取舍。
- 可复用的实现或可借鉴的模型。
- 新依赖、资源占用、维护与许可证影响。
- 来源、查看日期，以及还未验证的假设。

核实许可证后再复制代码或内嵌资源。只借鉴思路也应说明来源；不要根据 stars 数量推断适配质量。

新增付费服务、真实数据迁移或显著依赖成本超出现有授权时，给用户具体选项；常规内部实现选择由开发者处理，不重复审批。

调研 agent 只交有来源的结论，不实现产品、不自动创建开发聊天。主控根据结论冻结技术方案、确认范围，再向已授权的开发聊天分派。路线切换时保留旧实现，明确哪些能力本批不再追求。
