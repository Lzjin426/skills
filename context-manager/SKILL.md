# context-manager

## 触发条件

1. 用户要求"建立上下文""写 CONTEXT""写 AGENTS""初始化项目上下文"。
2. 会话超过 10 轮、完成关键任务、做出重要决策、或用户明确说"写交接"。
3. 用户说"会话太长了""换个会话继续""整理一下上下文"。

## 输出原则

- **只写结论和状态，不写过程细节。**
- **能一句话说清就不写两句。**
- **不复制大段代码、日志、公式。**
- **不堆砌内容，不追求完整，只保留关键信息。**
- **核心目标：下一个 agent 读完后能立刻上手，且上下文窗口不被塞满。**

## 三种输出

### 1. AGENTS.md（项目级规则）
路径：`项目根目录/AGENTS.md`

内容：
- 核心原则：目标导向，不发散。
- 先读 CONTEXT.md 和最新交接文档。
- 每次只做一个用户明确的交付物。
- 不主动调用任何 skill。
- 默认局部修改，不重构。

### 2. CONTEXT.md（项目级上下文）
路径：`项目文档目录/CONTEXT.md`

内容：
1. 项目介绍：研究问题 + 方法 + 当前卡点。
2. 当前目标：论文最终结论 + 本轮交付物。
3. 当前阶段。
4. 关键术语。
5. 数据口径。
6. 禁止事项。
7. 当前任务。

### 3. 交接文档（会话级状态）
路径：`项目文档目录/交接/会话交接_YYYY-MM-DD.md`

内容：
1. 本次目标。
2. 已完成。
3. 已决策。
4. 未决定。
5. 下一步。
6. 关键文件路径。
7. 注意坑。

## 执行流程

1. 先问用户："要建立/更新哪种文档？AGENTS / CONTEXT / 交接，还是全部？"
2. 读取现有文档（如果存在），只保留仍有效的信息。
3. 写入新文档。
4. 告诉用户文件路径和一句话摘要。
5. 不运行代码、不修改项目文件、不画图。

## 禁止事项

- 不要把大段代码塞进文档。
- 不要罗列所有历史会话。
- 不要写冗长解释。
- 不要在未经用户同意时更新 AGENTS.md 和 CONTEXT.md。
